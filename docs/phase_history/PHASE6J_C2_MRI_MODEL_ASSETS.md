# Phase 6J-C2 — Isolated MRI model asset qualification

Baseline: `phase6-accurate-surfaces` at `6d56440d33a5fc3309bb64445c1949bccdc41b22`.

The pinned upstream TotalSegmentator **v2.18.0** `total_mr` task consists of default datasets **850 and 851**, fast dataset **852**, and fastest dataset **853**. The installed task mapping and official folder identities must match before any acquisition. For explicit acquisition, the pinned downloader tasks are `total_mr` (850/851) and `total_fast_mr` (852/853). Exact folder names and release version `v2.5.0-weights` are pinned by this step. Only the `total_mr` task is in scope; no other MR tasks are supported by this change.

All assets are isolated under `<data-dir>/segmentation/providers/totalsegmentator-mri/2.18.0/`; the existing CT `totalsegmentator/2.18.0` root, CT manifests, stored studies, and other provider configurations are never touched. Downloads occur **only** after a separate explicit `--accept-download` invocation. The private MRI acquisition log stays in the separate MRI root, and is not included in handoffs. Models are never downloaded during application or automated tests. An interrupted acquisition remains unsealed and execution-ineligible.

The asset manifest records task identities, exact dataset directories, file paths, sizes and SHA256 values. It is verified against the actual inventory on each read; missing, added, empty, linked, changed or renamed files fail closed. Required `dataset.json`, `plans.json`, and `checkpoint_final.pth` must be present in each model folder. The first seal is atomic/exclusive; an existing sealed manifest is not automatically rewritten to accept changes. A seal establishes **local asset integrity and provenance relative to the first seal**, not authenticity of upstream releases or accuracy of the anatomical model. Manufacturer-provided SHA256/signature comparisons would be needed for independent upstream authenticity.

The `--inspect` mode is read-only and returns `UNQUALIFIED_OR_NOT_SEALED` when no qualified assets are present. Explicit acquisition requires a separately reviewed user action and network access, and may need substantial disk/time. Before C2 closure, capture the inspected task map, downloads, manifest hash, and real verification output (never patient data or model weight files). Neither asset qualification nor CUDA detection proves the MRI model fits in the RTX 2060 VRAM. No provider registration, MRI job, actual inference, UI enablement, CT pipeline edit, new clinical claim, or Git commit is performed by this patch. Actual execution and device-resource evaluation are Phase 6J-C3/C5; anatomical surface/MPR label-map presentation is Phase 6J-D.
