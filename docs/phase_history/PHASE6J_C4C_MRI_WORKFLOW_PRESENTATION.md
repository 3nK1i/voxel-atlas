# Phase 6J-C4C — Read-only MRI job presentation and UI isolation

Authoritative baseline: `phase6-accurate-surfaces` at `17da4824cb0f10e213b7be423dbad631ed78082e` (6J-C4B).

C4C integrates read-only, MRI-specific job status with the existing study-bound segmentation workflow and browser panel. The normal application still registers only the C4A **unavailable** `totalsegmentator/total_mr` descriptor: it does **not** register `MRIStudyBoundProvider`, authorize C3B, start TotalSegmentator MRI, or import MRI masks through the CT-only Phase 5C label-map worker. A previously recorded MRI job is visible only if its immutable study/series/modality, canonical volume creation time, descriptor SHA256 and artifact SHA256, and task/provider all match the current qualified MR source. All job messages in read-only MRI snapshots are fixed, privacy-safe application text. A matching completed job is shown as output recorded, never as a ready label map or validated inference.

The server refuses MRI start and finalization through the standard workflow while C4C presentation-only mode is active. Cancellation, if an otherwise qualified MRI job already exists, is scoped to that exact bound job. The browser enforces the same read-only policy, rejects stale/wrong study or selected-series responses, and clears old workflow/overlay state on study, series or volume revision changes. Pre-volume MRI admission and CT paths retain their existing behavior. This step does not claim MRI sequence suitability or clinical validation.

The Phase 6D0 regression assertion for a missing MRI provider is updated from `unsupported` to `unavailable`, matching the model routing introduced in Phase 6J-B1. The B1/B2B source-contract assertions accept the current cache-busted C4C script revision; no earlier behavior is weakened.

Acceptance: inspect exact guarded source diff; run targeted MRI and browser tests, the Phase 6D0 CT regression, and the full pre-existing C4B→C4A→C3B→CT chain on the user's own development checkout. Then manually verify the existing sample MRI has correct `total_mr` identity, disabled Start, no CT label map, and no stale UI status when switching to/from CT. Normal model execution and MRI label import remain excluded until separately authorized C5 and Phase 6J-D respectively. Do not commit patient data, `.env`, weights, study volumes, session logs, or authentication material.
