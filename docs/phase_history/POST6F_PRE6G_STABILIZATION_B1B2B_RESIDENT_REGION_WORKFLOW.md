# Post-6F / Pre-6G Stabilization B1B2B — reversible Direct-CT region workflow

Base: GitHub `phase6-accurate-surfaces` HEAD `60d66b9dc3175a9656c1faadbfa09486db9ad74c` with the B1B2A patch applied and uncommitted. B1B2B extends that same working-tree patch. Do not deploy directly to production or change patient study files.

The existing isosurface (VXVS) remains the authority. Only after an explicit **Build Surface** request is completed does the browser request display labels for the **exact resident surface ID and VXVS payload hash**. The authenticated `GET /api/studies/latest/volume-surface/regions?surface_id=...` route rejects nonresident/stale surfaces; it NEVER calls surface extraction. The isolated region worker rechecks immutable canonical source and complete resident VXVS hashes, reverses the exact Patient-LPS affine to map the already extracted vertices into index space, applies the B1B1 conservative broad-support association and returns one uint8 label per **existing triangle in its original order**. Label 0 means unresolved/other and remains visible. No patient, table, bone, artifact, or clinical inference is claimed by a region label.

Region evidence is a distinct, no-store binary payload with study/surface identity bound indirectly via the exact surface ID, source VXVS hash, label SHA256, triangle count and three face counts. The browser independently verifies the evidence against its still-resident surface and aborts stale, mismatched or malformed results. The initial selection is always **Full geometry**. The region selector only enables if both ranked regions have faces, never auto-hides either. Both explicit hide choices only change the resident GPU index display range, keeping the original geometry, original triangle order and original SHA/provenance available. Full geometry restores the exact original buffer with no extraction, reupload of source, or calibration change. Source/mode/profile transitions still use the resident mesh.

No automatic classification: **Region 1 is not universally the table; Region 2 is not universally the skull**. If both qualified regions are present, inspect each with the toggle and restore Full geometry whenever anatomical content might be hidden. This control changes visualization only; any future 6G metrics must evaluate the complete original surface. Direct-CT regions are unavailable when a single broad-support region is present or when threshold ordering is not qualified. Nothing is changed in segmentation, MPR, Patient LPS, CT isovalue, canonical volume, source provenance or existing Fidelity/Presentation material logic.

Test locally: `bash scripts/run_post6f_pre6g_stabilization_b1b2b_checks.sh`. This runs new synthetic region worker and authenticated API checks, browser exact-surface hash/stale-response tests, B1B2A and earlier regression, compile, syntax and diff checks. Actual real-study visual qualification **has not been performed in this source-only package**. On the authorized local test deployment, use the existing real CT without exporting patient data: build 300 HU; observe the region selector; toggle one region at a time; rotate to check anatomy/occluder; return Full geometry and verify the sheet and complete count restore. Change Volume/Surface/Combined mode, clipping and Fidelity/Presentation profile and confirm the region display remains stable and no re-extraction occurs; clear surface/change study and confirm control disables. For a study without two separated broad-support regions, the selector must remain disabled. Confirm login heading only once the separately approved production deployment is performed.

The patch does not perform clinical validation, alter production, commit/push, or establish whether either ranked region represents patient anatomy. Remaining Stabilization B work: visual qualification on the real study, then independent lighting correction (B2), followed by Phase 6G quantitative fidelity on the full original source-aligned geometry.
